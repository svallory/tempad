# Stints Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fold maneuvers back into their quest instead of counting each as its own stint. A stint below `stint_min_minutes` is dismissed at close time rather than reported. A session can declare several quests active at once, each with an alias (`Q1..Qn`) the verifier places segments against, plus a `--done` to retire one. A declaration's `--plan` becomes the list of stints the verifier is asked to match against (`P<n>.<m>` aliases) before it ever proposes a new one, closing the gap that made every small thing its own stint.

**Architecture:** Strictly serial — Task 1 → Task 2 → Task 3, each merged before the next starts. Task 1 (minimum duration) is independent of multi-quest declarations and the plan grain: it only touches `lifecycle.ts`'s close paths, one migration, and report/eval filters, so it lands first and cleanly. Task 2 (active quests) depends on Task 1 only for the `stintMinMinutes` config field existing on `W5Config` (used by Task 2's `declare`-question suppression) — it rewrites `declarations.ts`, `window.ts`, `prompt.ts`, `classifier.ts`, and `apply.ts`'s quest resolution around `activeDeclaredQuests`. Task 3 (skill, README, eval metrics) depends on Task 2's `Q`/`P`/`S`/`new:` selector shapes and `--done` existing, since its eval fixtures and skill examples exercise them.

**Tech Stack:** Bun 1.3, `bun:sqlite`, TypeScript strict, `bun test`. No new runtime dependencies.

**Spec:** `docs/specs/2026-09-07-stints-design.md`. Builds on `docs/specs/2026-09-07-declared-quests-design.md` and `docs/specs/2026-09-06-activity-continuity-design.md` (read for existing conventions: `EventStore`, `applyIncremental`, `Projection`, `ClassifierWindow`/`ClassifierResult`, `W5Config`, `openStintContinuing`, `currentDeclaredQuest`, the `stintAliases` scheme this plan partly renames).

## Global Constraints

- Same as prior w5 plans: bun only, full-word identifiers, no `any`, no non-null assertions, commits `type(w5): summary`, one per task.
- A pure `ALTER TABLE ... ADD COLUMN` migration gets `runMigration`'s tolerant per-statement path in `src/db/database.ts`; keep it in its own file, never mixed with a `CREATE TRIGGER` body — matching `0008_declared_quests.sql`'s precedent.
- `quests`, `stints`, `traces`, `questions` are projection tables owned by `src/intent/projections/quest.ts` and `stint.ts`, not by a migration — a new column goes into the projection's own `createSql` (fresh database) _and_ a migration's `ALTER TABLE` (existing database).
- Tests never call the network or the real `TEMPAD_HOME`; classifiers in tests are fakes implementing `Classifier`.
- Declarations are events (`quest.declared`), never a new mutable table — `activeDeclaredQuests` queries `events` directly, matching `currentDeclaredQuest`'s existing pattern.
- No banned words (`docs/specs/2026-09-07-ubiquitous-language.md`'s list): `objective`, `purpose`, `intent` (as a domain word), `step`, `task`, `goal`, `activity`, `action`, `"session quest"`. Use `outcome`, `stint`, `quest`, `maneuver`.

  ```ts
  function dismissIfBelowMinimum(
    store: EventStore,
    database: Database,
    stintId: string,
    closedAt: string,
    minMinutes: number,
  ): void {
    const row = database
      .query(
        `SELECT
           (SELECT SUM((julianday(traces.ended_at) - julianday(traces.started_at)) * 1440)
              FROM traces WHERE traces.stint_id = ? AND traces.retracted_at IS NULL) as traceMinutes`,
      )
      .get(stintId) as { traceMinutes: number | null };
    if ((row.traceMinutes ?? 0) >= minMinutes) return;
    applyIncremental(
      database,
      store.append({
        actor: "system",
        kind: "stint.dismissed",
        subject: stintId,
        at: closedAt,
        payload: { reason: "below minimum" },
      }),
    );
  }
  ```

- New export in `declarations.ts`:
  ```ts
  export interface ActiveDeclaredQuest extends DeclaredQuest {
    alias: string;
  }

  export function activeDeclaredQuests(
    database: Database,
    input: { sessionId: string; at: string },
  ): ActiveDeclaredQuest[] {
    const rows = database
      .query(
        `SELECT payload, at FROM events
          WHERE kind = 'quest.declared' AND json_extract(payload, '$.session_id') = ?
            AND json_extract(payload, '$.scope') = 'session' AND at <= ?
          ORDER BY at ASC, id ASC`,
      )
      .all(input.sessionId, input.at) as { payload: string; at: string }[];

    const active = new Map<string, { plan: string[]; at: string }>();
    for (const row of rows) {
      const payload = JSON.parse(row.payload) as {
        quest_id?: string;
        plan?: string[];
        done?: boolean;
      };
      const questId = payload.quest_id;
      if (!questId) continue;
      if (payload.done === true) {
        active.delete(questId);
        continue;
      }
      active.set(questId, { plan: payload.plan ?? [], at: row.at });
    }

    const result: ActiveDeclaredQuest[] = [];
    let aliasNumber = 0;
    for (const [questId, entry] of active) {
      const quest = database
        .query("SELECT title, outcome FROM quests WHERE id = ? AND retracted_at IS NULL")
        .get(questId) as { title: string; outcome: string | null } | null;
      if (!quest) continue;
      aliasNumber += 1;
      result.push({
        questId,
        title: quest.title,
        outcome: quest.outcome,
        plan: entry.plan,
        scope: "session",
        parentSessionId: null,
        alias: `Q${aliasNumber}`,
      });
    }
    return result;
  }
  ```
