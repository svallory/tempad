# Web UI implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `apps/web` — a bun + Elysia + Marko app, components from marko-ui, giving the Hero a live Today/Week/Quests view and a way to publish read-only client reports at `/r/<token>`. No SQL in the app that duplicates a core query; every write goes through `packages/core`.

**Architecture:** Task 1 scaffolds the moon project, the Elysia server, Marko rendering wired through whichever of the two paths in the spec's Open Questions turns out to work, marko-ui installed, and the `tempad web` CLI command — everything else depends on this shell existing and rendering at least one route. Task 2 (depends on 1) adds the SSE endpoint and the Today view, including the questions answer form — the first real use of the fragment-refresh mechanism task 1's layout must support. Task 3 (depends on 1 only, can run in parallel with 2) adds Quests and Week — neither needs SSE fragments beyond what task 2 already proves out, but both need task 1's layout and routing conventions. Task 4 (depends on 1 only, parallel with 2 and 3) adds the `shared_reports` migration, publish/revoke, `/r/<token>`, and the Reports view.

**Tech Stack:** Bun 1.3.14, Elysia, Marko 6, marko-ui (component library, exact package name confirmed in task 1 — see spec's Open Questions), `bun:sqlite` via `packages/core`, TypeScript strict. No test framework beyond `bun test`.

**Spec:** `docs/specs/2026-09-06-web-ui-design.md`. Builds on `docs/specs/2026-09-05-intent-model-and-w5-hook-design.md` (event catalog, `EventStore`, `applyIncremental`) and `docs/specs/2026-09-06-activity-continuity-design.md` (activity lifecycle fields this task's queries read: `close_reason`, `continues`).

## Global Constraints

- bun only, full-word identifiers, no `any`, no non-null assertions, commits `type(web): summary`, one per task.
- `apps/web` is a new moon project (`layer: "application"`), added to the existing `apps/*` workspace glob — no change to `.moon/workspace.yml` or root `package.json`'s `workspaces` array needed, both already glob `apps/*`.
- The app imports `packages/core`'s exported functions (`loadConfig`, `openDatabase`, `loadIntentConfig`, query functions, `api.ts` functions) as a workspace dependency (`"@tempad/core": "workspace:*"` in `apps/web/package.json`) — never reaches into `packages/core/src/**` with a relative path across the package boundary.
- Every new core function this plan adds (`queryOpenActivity`, `queryAskedQuestions`, `queryQuestsByState`, `confirmQuest`/`mergeQuest`/`rewordQuest`/`dismissQuest`, `loadWebConfig`) is tested in `packages/core`'s own `bun test` with a fixture database, independent of the web app being able to render anything — `apps/web`'s own tests hit real Elysia routes against a fixture database and assert on HTML/status, not on core's internals a second time.
- Migration files that are pure `CREATE TABLE`/`CREATE INDEX` (the `shared_reports` migration) do not need the tolerant per-statement ALTER path — that tolerance in `src/db/database.ts`'s `runMigration` exists for `ALTER TABLE ... ADD COLUMN` statements specifically; a fresh `CREATE TABLE` in its own migration file runs as one statement and needs no special handling.
- No app in this plan ever imports `packages/core/src/intent/cli.ts` or `packages/core/src/w5/cli.ts` — those are CLI entrypoints (they call `parseArgs`, `console.error`, `process.exit`-shaped `return` codes), not reusable API surfaces. Every core capability the app needs is a plain exported function from a non-`cli.ts` module.

## Interfaces task 1 produces, consumed by tasks 2, 3, 4

- `apps/web/src/server.ts`: `export function createServer(input: { database: Database; config: Config; intentConfig: IntentConfig; webConfig: WebConfig }): Elysia` — builds and returns the Elysia app with routes registered, but does not call `.listen()`; task 1's own test and every later task's tests call `createServer(...)` directly against an in-memory or fixture database and use Elysia's own request-handling (`app.handle(request)`) rather than binding a real port, so no test in this plan ever binds `4242` or needs `flock`-style port coordination.
- `apps/web/src/cli-command.ts`: `export function runWebCommand(args: string[]): Promise<number>` — parses `--host` and any other future flags, loads `Config`/`IntentConfig`/`WebConfig`, opens the database, calls `createServer`, and `.listen(webConfig.port)`; wired into `packages/core/src/cli.ts` as the `tempad web` subcommand (`if (command === "web") return runWebCommand(rest);` — added next to the other command branches in `main()`).
- `packages/core/src/web/config.ts`: `WebConfig` interface and `loadWebConfig(tomlPath: string): WebConfig` exactly as specified in the spec's Config changes section, following `loadIntentConfig`'s pattern (`Bun.TOML.parse`, default when file or `[web]` section absent, no throw).
- `apps/web/src/layout.marko`: the shared page chrome (nav linking Today/Week/Quests/Reports, marko-ui's base styles imported) every hero-route template extends; the exact `<import>`/composition mechanism (Marko 6 native-tag composition vs. a `<slot>`-style API) is whatever task 1 confirms works when it resolves the Open Questions item on `template.render`.
- Fragment-request convention: every hero-route GET handler checks a `fragment` query parameter (e.g. `?fragment=today-timeline`); when present and recognized, the handler renders only that named partial's Marko template and returns it with no layout wrapper; when absent, it renders the full page. Task 1 documents this convention in `apps/web/CLAUDE.md` (new file, since `apps/web` has no `CLAUDE.md` yet) so tasks 2-4 apply it identically instead of inventing per-view mechanisms.

  ```ts
  export interface WebConfig {
    port: number;
    host: string;
    pollSeconds: number;
  }

  export function defaultWebConfig(): WebConfig {
    return { port: 4242, host: "127.0.0.1", pollSeconds: 2 };
  }

  export function loadWebConfig(tomlPath: string): WebConfig {
    if (!existsSync(tomlPath)) return defaultWebConfig();
    const parsed = Bun.TOML.parse(readFileSync(tomlPath, "utf8")) as Record<string, unknown>;
    const config = defaultWebConfig();
    const web = parsed.web as Record<string, unknown> | undefined;
    if (!web) return config;
    return {
      port: typeof web.port === "number" ? web.port : config.port,
      host: typeof web.host === "string" ? web.host : config.host,
      pollSeconds: typeof web.poll_seconds === "number" ? web.poll_seconds : config.pollSeconds,
    };
  }
  ```

  ```ts
  import { join } from "node:path";
  import { parseArgs } from "node:util";
  import { loadConfig, openDatabase, loadIntentConfig } from "@tempad/core";
  import { loadWebConfig } from "@tempad/core/web/config";
  import { createServer } from "./server";

  export async function runWebCommand(args: string[]): Promise<number> {
    const { values } = parseArgs({
      args,
      options: { host: { type: "string" } },
      strict: true,
    });
    const config = loadConfig();
    const database = openDatabase(join(config.home, "tempad.db"));
    const intentConfig = loadIntentConfig(join(config.home, "tempad.toml"));
    const webConfig = loadWebConfig(join(config.home, "tempad.toml"));
    const host = values.host ?? webConfig.host;
    if (host !== "127.0.0.1" && host !== "localhost") {
      const password = process.env.TEMPAD_WEB_PASSWORD;
      if (!password || password.trim().length === 0) {
        throw new Error("TEMPAD_WEB_PASSWORD must be set in .env when --host is not loopback");
      }
    }
    const app = createServer({ database, config, intentConfig, webConfig });
    app.listen({ hostname: host, port: webConfig.port });
    console.log(`tempad web listening on http://${host}:${webConfig.port}`);
    return 0;
  }
  ```

  ```ts
  export interface OpenActivityRow {
    id: string;
    questId: string | null;
    questTitle: string | null;
    objective: string;
    openedAt: string;
    org: string | null;
    project: string | null;
  }

  export function queryOpenActivity(
    database: Database,
    options: { org?: string } = {},
  ): OpenActivityRow | null {
    if (!hasIntentTables(database)) return null;
    const conditions = ["a.closed_at IS NULL", "a.retracted_at IS NULL"];
    const params: string[] = [];
    // org filter resolved through the activity's most recent trace's session,
    // same join shape queryTraceIntervals uses, since activities carry no
    // org/project column of their own.
    const row = database
      .query(
        `SELECT a.id as id, a.quest_id as questId, a.objective as objective, a.opened_at as openedAt,
                q.title as questTitle, s.org as org, s.project as project
           FROM activities a
           LEFT JOIN quests q ON q.id = a.quest_id
           LEFT JOIN traces t ON t.activity_id = a.id AND t.retracted_at IS NULL
           LEFT JOIN claude_sessions s ON s.id = t.session_id
          WHERE ${conditions.join(" AND ")}${options.org ? " AND LOWER(s.org) = ?" : ""}
          ORDER BY a.opened_at DESC LIMIT 1`,
      )
      .get(...(options.org ? [options.org.toLowerCase()] : [])) as
      | (OpenActivityRow & { questConfirmed?: never })
      | null;
    return row;
  }

  export interface AskedQuestionRow {
    id: string;
    traceId: string;
    sessionId: string | null;
    text: string;
    isSwitch: boolean;
    activityObjective: string | null;
    questTitle: string | null;
  }

  export function queryAskedQuestions(
    database: Database,
    options: { org?: string } = {},
  ): AskedQuestionRow[] {
    if (!hasIntentTables(database)) return [];
    const conditions = ["qu.state = 'asked'"];
    const params: string[] = [];
    if (options.org) {
      conditions.push("LOWER(s.org) = ?");
      params.push(options.org.toLowerCase());
    }
    return database
      .query(
        `SELECT qu.id as id, qu.trace_id as traceId, t.session_id as sessionId, qu.text as text,
                qu.is_switch as isSwitch, a.objective as activityObjective, q.title as questTitle
           FROM questions qu
           JOIN traces t ON t.id = qu.trace_id
           LEFT JOIN claude_sessions s ON s.id = t.session_id
           LEFT JOIN trace_links tl ON tl.trace_id = t.id AND tl.superseded_at IS NULL
           LEFT JOIN activities a ON a.id = tl.activity_id
           LEFT JOIN quests q ON q.id = a.quest_id
          WHERE ${conditions.join(" AND ")}
          ORDER BY qu.id ASC`,
      )
      .all(...params)
      .map((row) => ({ ...(row as object), isSwitch: (row as { isSwitch: number }).isSwitch === 1 })) as AskedQuestionRow[];
  }
  ```

- `packages/core/src/intent/api.ts` gains, mirroring `answerQuestion`'s existing shape exactly:
  ```ts
  export function confirmQuest(store: EventStore, database: Database, questId: string, actor: Actor): void {
    applyIncremental(database, store.append({ actor, kind: "quest.confirmed", subject: questId, payload: {} }));
  }

  export function mergeQuest(store: EventStore, database: Database, questId: string, intoQuestId: string, actor: Actor): void {
    applyIncremental(database, store.append({ actor, kind: "quest.merged", subject: questId, payload: { into: intoQuestId } }));
  }

  export function rewordQuest(store: EventStore, database: Database, questId: string, title: string, objective: string | undefined, actor: Actor): void {
    applyIncremental(database, store.append({ actor, kind: "quest.reworded", subject: questId, payload: { title, objective } }));
  }

  export function dismissQuest(store: EventStore, database: Database, questId: string, reason: string, actor: Actor): void {
    applyIncremental(database, store.append({ actor, kind: "quest.ended", subject: questId, payload: { reason } }));
  }
  ```

- `apps/web/src/routes/events.ts`: `export function registerEventsRoute(app: Elysia, deps: ServerDeps): Elysia` — `GET /events` returns a `Response` with `content-type: text/event-stream` backed by a `ReadableStream` whose `pull`/interval polls `SELECT id, kind FROM events WHERE id > ? ORDER BY id ASC` every `deps.webConfig.pollSeconds * 1000` ms, starting from `SELECT MAX(id) FROM events` (or `0` if null) captured at connection time; on each poll with new rows, enqueues one `event: intent\ndata: {"lastEventId": <max id>, "kinds": [...]}\n\n` chunk (kinds deduplicated via a `Set`); the interval is cleared in the stream's `cancel()` callback so a closed connection doesn't leak a timer — this is the one piece of task 2 that needs an actual timer in a test, so `events.test.ts` uses `Bun.sleep` around a short `pollSeconds: 0.05` (50ms) config value rather than mocking time, and asserts on the raw decoded SSE text after reading a bounded number of chunks from the response body's reader (with a test-level timeout, not a production one).
- `apps/web/src/routes/today.ts`: `export function registerTodayRoute(app: Elysia, deps: ServerDeps): Elysia` — `GET /` (fragment name `today-timeline` for the activities+side-quests section, `today-questions` for the question list) calls `queryActivities`, `querySideQuests`, `queryOpenActivity`, `queryAskedQuestions` with `range = { from: <today's date in deps.config.tz>, to: <same>, timeZone: deps.config.tz }`, renders `today.marko`. `POST /questions/:id/answer` (form body `quest`, `why`) calls `answerQuestion` from `api.ts`, then re-renders and returns the `today-questions` fragment (no redirect, so the answering tab updates in place without a full navigation).
- `apps/web/src/static/refresh.js`: vanilla script, no build step, served as a static asset by Elysia's static plugin or a plain route returning `content-type: application/javascript`; opens `new EventSource("/events")`, on each `intent` message looks up `event.kinds` against a small object literal mapping kind prefixes (`"trace."`, `"activity."` → `today-timeline`; `"question."` → `today-questions`) to fragment names, and for each matched fragment does `fetch(location.pathname + "?fragment=" + name).then(r => r.text()).then(html => document.querySelector('[data-fragment="' + name + '"]').outerHTML = html)`; also re-runs that same fetch on the page's `visibilitychange` event when `document.visibilityState === "visible"`, per the spec's reconnect self-heal rule.

  ```ts
  export interface QuestStateRow {
    id: string;
    title: string;
    objective: string | null;
    confirmed: boolean;
    state: string;
    ownerKind: string;
    ownerId: string;
    activityCount: number;
    minutesTotal: number;
    lastEvidenceAt: string | null;
  }

  export function queryQuestsByState(
    database: Database,
    options: { confirmed?: boolean; org?: string } = {},
  ): QuestStateRow[] {
    if (!hasIntentTables(database)) return [];
    const conditions = ["q.retracted_at IS NULL"];
    const params: (string | number)[] = [];
    if (options.confirmed !== undefined) {
      conditions.push("q.confirmed = ?");
      params.push(options.confirmed ? 1 : 0);
    }
    const questRows = database
      .query(
        `SELECT q.id as id, q.title as title, q.objective as objective, q.confirmed as confirmed,
                q.state as state, q.owner_kind as ownerKind, q.owner_id as ownerId
           FROM quests q WHERE ${conditions.join(" AND ")} ORDER BY q.created_at DESC`,
      )
      .all(...params) as {
      id: string; title: string; objective: string | null; confirmed: number;
      state: string; ownerKind: string; ownerId: string;
    }[];

    return questRows.map((quest) => {
      const stats = database
        .query(
          `SELECT COUNT(a.id) as activityCount,
                  COALESCE(SUM((julianday(COALESCE(t.ended_at, t.started_at)) - julianday(t.started_at)) * 1440), 0) as minutesTotal,
                  MAX(t.ended_at) as lastEvidenceAt
             FROM activities a
             LEFT JOIN traces t ON t.activity_id = a.id AND t.retracted_at IS NULL
            WHERE a.quest_id = ? AND a.retracted_at IS NULL`,
        )
        .get(quest.id) as { activityCount: number; minutesTotal: number; lastEvidenceAt: string | null };
      return {
        id: quest.id,
        title: quest.title,
        objective: quest.objective,
        confirmed: quest.confirmed === 1,
        state: quest.state,
        ownerKind: quest.ownerKind,
        ownerId: quest.ownerId,
        activityCount: stats.activityCount,
        minutesTotal: stats.minutesTotal,
        lastEvidenceAt: stats.lastEvidenceAt,
      };
    });
  }
  ```

  ```ts
  export interface SharedReportInput {
    client: string;
    fromDate: string;
    toDate: string;
    title: string;
    html: string;
    password: string | undefined;
    now: string;
  }

  export async function publishSharedReport(database: Database, input: SharedReportInput): Promise<string> {
    const token = tokenFromRandomBytes(); // crypto.getRandomValues(new Uint8Array(32)), base64url-encoded
    const passwordHash = input.password ? await Bun.password.hash(input.password) : null;
    database
      .query(
        `INSERT INTO shared_reports (token, client, from_date, to_date, title, html, password_hash, created_at)
         VALUES (?, ?, ?, ?, ?, ?, ?, ?)`,
      )
      .run(token, input.client, input.fromDate, input.toDate, input.title, input.html, passwordHash, input.now);
    return token;
  }

  export interface SharedReportRow {
    token: string; client: string; fromDate: string; toDate: string; title: string;
    html: string; passwordHash: string | null; createdAt: string; revokedAt: string | null;
  }

  export function getSharedReport(database: Database, token: string): SharedReportRow | null {
    const row = database
      .query(
        `SELECT token, client, from_date as fromDate, to_date as toDate, title, html,
                password_hash as passwordHash, created_at as createdAt, revoked_at as revokedAt
           FROM shared_reports WHERE token = ?`,
      )
      .get(token) as SharedReportRow | null;
    return row;
  }

  export function revokeSharedReport(database: Database, token: string, now: string): void {
    database.query("UPDATE shared_reports SET revoked_at = ? WHERE token = ?").run(now, token);
  }
  ```
